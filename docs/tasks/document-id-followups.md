# document_id 전환 후속 과제와 우려사항

## 배경

문서 식별 기준을 이름에서 `document_id`(백엔드 DB의 UUID)로 바꾸는 작업이 `feat/document-id-lookup` 브랜치에 반영되어 있다.

| 커밋 | 내용 |
| --- | --- |
| `4dbe61f` | MARS 적재 요청(`POST /documents`)에 `document_id` 쿼리 파라미터 전달 |
| `e7c2499` | MARS 삭제를 id 기준으로 변경, `sources.document_id` 컬럼·마이그레이션·응답 필드 추가 |
| `398bb2b` | 삭제 호출 경로를 `/documents/{id}`에서 `/documents/by-id/{id}`로 수정 |

`398bb2b` 이전에는 MARS가 UUID를 파일명으로 해석해 항상 404를 반환했다. 그 결과 관리자 문서는 DB에서만 지워지고 청크가 남았고, 프로젝트 문서는 삭제가 실패했다.

이 문서는 전환 작업 중 확인했지만 이번 범위에서 처리하지 않은 항목을 정리한다. 2026-10-25 기준이다.

## 배포 전 확인 사항

머지 자체는 가능하지만, 운영에 배포하기 전에 아래 항목을 확인한다.

1. **MARS 배포 순서.** by-id 삭제 경로는 MARS `1bbecdc` 이후에만 있다. MARS를 먼저 또는 함께 배포한다.
2. **DB 마이그레이션.** `alembic upgrade head`로 `f3a4b5c6d7e8`(`sources.document_id`)을 적용한다. 컬럼이 없으면 AI 답변 저장이 실패한다.
3. **기존 문서의 id 불일치.** 아래 과제 1을 해결하기 전에는 기존 문서 삭제가 정상 동작하지 않는다.

## 미결 과제

### 1. 기존 문서의 id 불일치 — 배포 전 필수

id 전환 전에 적재된 문서는 MARS 청크의 `document_id`가 DB의 id와 다르다. MARS 마이그레이션(`scripts/migrate_document_id.py`)을 돌렸다면 `(project_id, source_doc)`마다 MARS가 따로 만든 uuid5가, 돌리지 않았다면 빈 값이 들어 있다.

이 문서들을 by-id로 삭제하면 MARS가 404를 반환한다.

- 관리자 문서: 404를 "이미 없음"으로 처리하므로 DB에서만 지워지고 청크는 검색에 계속 나온다. 오류가 드러나지 않는다.
- 프로젝트 문서: 404를 처리하지 않으므로 삭제가 계속 실패한다.

해결 방법을 정한다.

- (a) 마이그레이션 매핑 CSV로 MARS의 id를 DB id에 맞춘다.
- (b) 기존 문서를 DB id로 전부 재적재한다.

### 2. 프로젝트 문서 삭제가 MARS 404를 처리하지 않음

[`project_service.py`](../../app/services/project_service.py)의 `delete_project_document`는 `job_id`가 있으면 MARS 삭제를 호출하고, 404를 그대로 전파한다. 관리자 경로([`document_service.py`](../../app/services/document_service.py)의 `delete_document_admin`)는 404를 멱등 처리한다.

적재에 실패해 청크가 없는 문서도 `job_id`가 남아 있으면 삭제가 막힌다. 전환 이전부터 있던 동작이지만, 과제 1 때문에 발생 빈도가 높아진다.

### 3. DB ↔ MARS 정합성 점검

DB 문서 목록과 MARS `GET /documents` 목록을 `document_id`로 비교해 불일치를 찾고 복구한다. 설계 방향은 합의했고 구현은 보류했다.

| 분류 | 조건 | 처리 |
| --- | --- | --- |
| 색인 유실 | DB `done`, MARS에 없음 | 원본으로 재적재 |
| 고아 색인 | MARS에 있음, DB에 없음 | MARS에서 by-id 삭제 |
| 진행 중 | `pending`·`queued`·`running`이고 최근 변경 | 점검 제외 |
| 상태 불일치 | DB `error`, MARS 목록에 id 있음 | `done`으로 전환하고 경고 로그 |

상태 불일치를 `done`으로 전환할 수 있는 근거는 MARS 적재의 원자성이다. MARS는 적재가 실패하면 저널로 이전 상태를 복구하므로, 목록에 id가 있으면 적재가 끝까지 완료된 것으로 본다. 재시도는 같은 원본을 보내므로 이전 버전으로 복구된 경우에도 내용이 같다.

실행 시점은 다음 네 가지다. 모든 실행 결과는 백엔드 로그에 남긴다.

- 백엔드 시작 시: 탐지만
- MARS 재시작 감지 시: 탐지, 복구는 새벽 배치에서
- 매일 새벽: 탐지와 복구
- 관리자 수동 API: 탐지만(`GET`) 또는 복구까지(`POST`)

재개 전에 정할 것:

- 과제 1을 해결하기 전에는 자동 복구를 끄고 탐지만 둔다. 켜면 기존 청크는 모두 고아로, DB의 `done` 문서는 모두 유실로 판정된다.
- uvicorn 워커가 여러 개면 워커마다 스케줄러가 돌아 중복 실행된다. 운영 워커 수를 확인한다.
- 최근 변경 문서의 유예 시간(안 10분)과 1회 최대 복구 건수를 정한다. MARS 삭제는 BM25 전체 재빌드를 유발하고, 그동안 다른 적재는 409를 받는다.

`398bb2b` 이전에 생긴 고아 색인은 이 기능이 생기기 전까지 남아 있다.

### 4. 개정본과 구판의 공존

업로드할 때 같은 이름의 문서가 있는지 검사하지 않는다. 개정본을 올리면 새 id로 추가되고, 구판을 지우지 않으면 두 버전의 청크가 함께 검색되어 답변에 섞일 수 있다. 두 문서 모두 정상 상태이므로 정합성 점검으로는 찾을 수 없다. 파일명을 바꿔 올리면 같은 문서인지 시스템이 알 수 없다.

| 안 | 내용 | 고려 사항 |
| --- | --- | --- |
| A | 같은 범위에 같은 이름이 있으면 업로드 거부(409) | 구판 삭제부터 신판 적재 완료까지 검색 공백 |
| B | 신판이 `done`이 되면 구판 삭제 | 적재 중 두 버전 공존, 상태 추적 필요 |
| C | 같은 id를 유지하는 "개정" 기능 | MARS가 같은 id 청크를 원자적으로 교체해 공존 구간이 없음. 재적재 실패 시 구판으로 복구되므로 MARS `applied_at`과 DB `updated_at` 비교 필요 |

C를 우선 검토한다.

### 5. 프론트엔드 출처를 id로 조회

MARS(`test/openrouter`의 `426ff19`)는 출처에 `document_id`를 담아 보내고, 백엔드는 이를 저장해 응답에 포함한다. 프론트엔드는 아직 이 값을 읽지 않는다.

- `normalizeSource`가 `name`과 `page`만 남긴다.
- `SourceBadge`는 `findDocumentByName`으로 이름을 비교해 문서를 찾는다. 같은 이름이 여러 개면 적용 시점 기준으로 하나를 고르므로, 답변의 근거와 다른 문서가 열릴 수 있다.

`sources.document_id`가 `documents` 테이블에 항상 대응하지는 않는다. FK가 없고, 다음 경우에는 대응하는 행이 없다.

- 출처 저장 후 문서가 삭제된 경우
- id 도입 전 답변이거나 id가 없는 구 청크(NULL)
- MARS 마이그레이션으로 uuid5가 붙은 구 문서

따라서 프론트엔드는 id로 찾고, 없으면 이름으로 찾고, 그래도 없으면 클릭을 비활성화한다. 백엔드에서 조인한다면 LEFT JOIN을 쓴다.

## 그 밖의 우려사항

- **삭제 경로 테스트가 없다.** 기존 테스트 13개는 통과하지만 `delete_document`의 요청 URL과 404·409 처리를 확인하는 테스트는 없다.
- **테스트 실행 환경.** `.env`의 `DATABASE_URL`이 `mysql://`(동기 드라이버)라서 테스트 모듈 import 단계에서 실패한다. 실행할 때 `DATABASE_URL=sqlite+aiosqlite://`로 덮어써야 한다.
- **MARS 구조화 출력의 JSON 잘림(백엔드 변경과는 무관).** MARS `1bbecdc`에서 구조화 호출의 토큰 상한이 `STRUCTURED_MAX_TOKENS`(기본 512)로 바뀌었다. 커밋 주석에 따르면 Gemma 같은 외부 모델은 1024가 필요한데, 현재 MARS `.env`는 Gemma를 쓰면서 이 값을 설정하지 않았다. "JSON이 닫히지 않음" 오류의 유력한 원인이다.
